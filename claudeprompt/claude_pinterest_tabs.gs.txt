## ROLE AND GOAL

You are a senior front-end engineer and technical SEO working on **Finmatrix** (https://finmatrix.cloud), a free US personal-finance **calculator tools website**. The site is a static HTML/CSS/JS project (homepage `index.html`, a `main.js`, a `calculators/` folder, and a few article pages). The owner is based in India and targets a US audience.

**Business goal:** grow organic Google traffic and earn from (1) affiliate offers placed on calculator results and (2) display ads later (AdSense). **The owner will NOT write more articles.** The site is being repositioned as a dedicated calculator-tools site. Every tool page must carry enough built-in explanatory content to rank and to pass ad-network quality review, without relying on a blog.

## HARD RULES (read before touching anything)

1. **Never invent facts.** Do not fabricate tax brackets, limits, rates, APYs, bank claims, FDIC numbers, author credentials, testimonials, or affiliate URLs. If a figure can't be verified from an official source (IRS, SSA, CFPB, Federal Reserve, state revenue departments), leave a clearly marked `TODO: VERIFY` placeholder and list it in `TODO.md`. Do not guess.
2. **Affiliate links:** read them from a single config file. Use obvious placeholders (`https://example.com/REPLACE_ME`) until the owner supplies real ones. Never ship a link that looks real but isn't.
3. **No thin or duplicate pages.** Do not generate near-identical pages with only a city/state name swapped. Any scenario or state page must have genuinely different data and unique explanatory text.
4. **Preserve the existing design language** (dark theme, fonts, components) unless a change is required by a task below.
5. **Do not add new articles or blog posts.** Existing articles are being folded into calculator pages or redirected (see Phase 1).
6. **Finance is YMYL.** Every calculator must show its assumptions, cite sources, and display a disclaimer ("for educational purposes, not financial, tax or legal advice"). Calculation correctness matters more than features. Write unit tests for every formula.
7. Work in phases. After each phase, run the checks listed, commit with a clear message, and summarize what changed. If something is ambiguous, make the safest reasonable choice, record it in `DECISIONS.md`, and continue instead of stopping.

2. **Affiliate links:** replace every `href="#"` on the homepage with links resolved from `config/affiliates.json`. All affiliate links must use `rel="sponsored nofollow noopener"` and `target="_blank"`. Keep the advertiser disclosure visible near every affiliate block.

4. **"2025" cleanup:** find every "2025" in titles, H1s, badges, meta tags, JSON-LD, and article text; update to 2026 where the content applies, and fix tax-year facts. **Phase 1 checks:** no `href="#"` remains; no "2025" remains unless historically accurate; all affiliate links have the right `rel`; site search works; sitemap and robots exist; every old URL either resolves or redirects.

## PHASE 2: REUSABLE TOOL-PAGE TEMPLATE

Create one template (partial, component, or generator script, whichever fits the existing stack) and a data-driven setup so every calculator page includes:

- Unique `<title>` (under about 60 characters) and meta description (under about 155) built around the page's search phrase, plus canonical, Open Graph and Twitter tags.
- **H1 matching the target query**, and the calculator **above the fold**, usable without sign-up.
- Results area with a **shareable URL** (inputs encoded in query params, prefilled on load, canonical pointing to the base page).
- **"How this is calculated"** section (150–300 words): formula in plain language and a worked example using real numbers.
- **Assumptions and sources**: list inputs, the tax year used, and source links (from `config/tax-year.json`). Show a visible "Updated for the 2026 tax year · Reviewed [date]" line.
- **FAQ**: 4–6 questions with real, accurate answers (`<details>` is fine). Add `FAQPage` JSON-LD only if the content genuinely matches.
- **Related calculators** block (2–4 links) and a **"Next step"** chain (e.g. affordability → mortgage → refinance).
- **Affiliate result box** (Phase 5) and the disclaimer.
- JSON-LD: `WebApplication` (or `SoftwareApplication`) plus `BreadcrumbList`. Do not add fake ratings or review schema.
- Accessibility: labels on all inputs, keyboard-usable, adequate contrast, `aria-live` on results.
- Mobile-first, fast: no layout shift, no blocking third-party scripts.

Apply the template to the **5 existing top tools first**, starting with the debt payoff (avalanche vs snowball) calculator, then the others in priority order from `AUDIT.md`. Write unit tests for the formulas (compare against hand-calculated or published reference examples, and add edge cases like 0%, 0 balance, and very large inputs).
